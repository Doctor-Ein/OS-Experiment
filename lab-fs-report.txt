# Lab7 实验记录（File System）

## 一、实现概述

本次实验主要完成了两部分内容：扩展 xv6 文件系统以支持更大的文件，以及实现符号链接机制。

在 large file 部分，我将 inode 中的 direct block 数量从 12 调整为 11，并新增了一个 doubly-indirect block。核心工作集中在 `bmap()` 的扩展：在原有 direct 和 single indirect 的基础上，引入两级索引，使逻辑块号能够映射到更大的数据范围。同时对 `itrunc()` 进行了对应修改，确保在删除文件时能够完整释放包括二级间接块在内的所有数据块。

在 symbolic link 部分，我新增了文件类型 `T_SYMLINK`，并实现了 `symlink` 系统调用。符号链接本质上被当作一个普通文件处理，其数据块中存储目标路径。在 `open()` 中增加了解析逻辑：默认递归跟随符号链接，若设置 `O_NOFOLLOW` 则直接返回链接本身；同时通过设置最大递归深度来避免循环链接导致的死循环。

此外，对 Makefile 和测试代码做了少量调整，使测试能够覆盖关键路径但不会因文件规模扩大而显著拖慢执行时间。

---

## 二、实现中的关键问题

实验过程中主要遇到两个比较实际的问题。

一个是 large file 扩展后，`usertests` 中原本基于 `MAXFILE` 的测试会变得非常耗时。这里没有简单地“跑满”，而是改为覆盖到 double indirect 的入口即可，这样既能验证正确性，也避免了不必要的时间消耗。

另一个问题出现在 `itrunc()`：double indirect 的释放逻辑容易遗漏中间的索引块。一开始只释放了数据块，后来通过明确两级结构（先一级索引，再二级数据块）的遍历顺序，才保证释放完整。

在符号链接部分，最大的坑是递归解析。一旦出现循环链接就会卡死，因此最终通过限制解析深度来规避这个问题，这也是一个比较常见的工程处理方式。

## 三、一些实现理解

这次实验有一个比较清晰的主线：

* large file 本质是“多级索引结构”的扩展；
* symbolic link 本质是“路径重定向”的实现。

前者更偏数据结构，把一维索引扩展为树状结构；后者更偏语义处理，把路径解析从一次变为多次。

特别是在 `bmap()` 中，从“直接索引 → 一级间接 → 二级间接”的过渡，其实就是一个很典型的分层映射过程；而 symbolic link 的实现，则让我更直观地理解了路径解析是在内核中逐步展开的，而不是一次性完成。
